# Weekly Update — 2026-11-01

## Executive summary

This week turns “sandboxing” from a container feature into a lifecycle-and-evaluation discipline. Amazon's Sandman report, backed by 3.13 million production sandbox creations, shows that caller cancellation does not cancel resource creation, a failed response does not prove that no resource exists, and a valid grade requires a separate environment whose image, network, limits, tests, and other run conditions are checked. Temporal Python SDK 1.35.0 adds the same lesson for durable workflows: validators must demonstrably execute, replay compatibility is an upgrade invariant, and ordered progress state cannot be assumed when codecs or cancellation intervene. TRL 1.17.0 separately shows that agentic post-training can optimize the wrong signal when the sampler and trainer disagree on probability support or numeric precision. On the evolving frontier, Adaptive Memory Index Evolution distinguishes stored content from persistent access state, while Evolving Agent Teams provides a reproducible example of changing team structure in response to measured plateaus. The steady-state plan remains correct; this week's experiment should extend the existing conformance pack with lifecycle ownership, clean-grader, replay-upgrade, and negative-control cases.

## Impact on the knowledge map

- **Confirmed:** Isolation, authorization, evaluator integrity, and recovery are system properties, not model properties. Canonical file/network identities, bounded operations, clean grading, and deterministic failure handling remain required.
- **Changed:** External resources now require an explicit lifecycle owner that survives timeout, cancellation, and ambiguous API errors. Durable upgrades require replay-compatibility testing or worker versioning/drain. Memory access/index state is separated from stored content and exposure policy. Post-training reward curves are trusted only after sampler/trainer support, precision, policy-version, and objective parity checks.
- **Challenged:** “The caller was cancelled, so the work stopped”; “a fresh container implies a valid grade”; “declaring a validator means it runs”; “the sampler's logged probability can be consumed directly by the trainer”; and “a larger fixed team is the main path beyond a local optimum.”
- **Still uncertain:** How Sandman's lessons transfer to hostile multi-tenant sandboxes; whether AMIE avoids popularity feedback loops under long-lived corpus drift; whether Evolving Agent Teams generalizes beyond objective-rich optimization tasks; how broadly TRL's fixes affect other rollout/trainer pairs; and whether signed boundary records materially improve incident response at production scale.

## Decisions and actions

- **Study deeply:** Sandman's lifecycle-ownership and grading sections; TRL's support/precision mismatch; Temporal's validator and replay-upgrade notes.
- **Prototype/test:** Cancel during create/delete, ambiguous create errors, cleanup after a second cancellation, clean-grader run-condition probes, validator negative controls, replay across a behavior-changing upgrade, sampler/trainer log-probability parity, and bounded memory-index updates.
- **Record only:** Claude Code and LangGraph release-specific flags and stream fixes; MCP package/runtime versions; Tracekit's current implementation constraints.
- **Ignore/watch:** Multi-agent systems without matched budgets and executable objectives; sandbox claims without an explicit threat model; post-training speed claims without reward-integrity checks; memory gains reported only as retrieval accuracy.

## Three highest-priority items

1. Turn Sandman's incident ledger into portable lifecycle tests: cancellation during create, error-after-create, lost delete replies, second cancellation during cleanup, authenticated ingress, enforced egress, digest-pinned images, and separate clean grading.
2. Add durable-workflow gates from Temporal 1.35.0: a validator negative control, monotonic heartbeat/progress state, replay of old histories on the candidate worker, and an explicit drain/version decision for incompatible upgrades.
3. Reproduce TRL's sampler/trainer parity check on a tiny rollout: compare candidate-token support, logged probabilities, policy version, dtype, masks, and objective before allowing an agentic post-training run to consume compute.

## One recommended investment

Spend **four focused hours** extending the production-hardening suite into a **sandbox-lifecycle and oracle-environment gate**:

- **45 min:** draw resource states and owners from request through create, handoff, cancellation, delete, and ambiguous error.
- **75 min:** add 6–8 fault-injection cases for cancel-during-create, error-after-create, lost delete reply, duplicate retry, second cancellation, orphan process, and stale progress marker.
- **60 min:** run the same task in a separate grader with a digest-pinned image; assert reference patch passes, empty patch fails, and network/CPU/memory/user/time/test conditions match the declaration.
- **45 min:** add one validator negative control and replay an old history against the candidate worker version.
- **15 min:** record deploy-blocking thresholds and which failures require reconciliation rather than retry.

**Expected output:** a 10–15-case, framework-independent gate that catches leaked resources, false cleanup, contaminated grades, inert policy validators, replay-breaking upgrades, and duplicate or stale progress. Keep the memory-index and multi-agent ideas as follow-on experiments until this gate passes.
