# Weekly Update — 2026-09-27

## Executive summary

The core production-agent mental model held: context, memory, workflow state, tools, and observability remain separate concerns. The highest-signal change was MCP TypeScript SDK 2.1.0, which moved capability-scoped authorization, sender-constrained credentials, and request bounds closer to the tool-dispatch boundary. Mem0's releases exposed a more general production lesson: a memory API can report successful writes or plausible retrieval scores while persistence, filters, or ranking are wrong, so memory correctness must be tested independently. A new study of reusable agent skills also suggests that skill activation—not merely skill content—is a first-class harness evaluation target. The coming week should remain on the planned Week 2 focus: memory, retrieval, and durable execution.

## Impact on the knowledge map

- **Confirmed:** Tool authorization, credential binding, and input/resource limits must be deterministic and enforced before dispatch. Durable queues belong in server-owned workflow state. Memory retrieval must be evaluated both independently and end-to-end.
- **Changed:** The memory stance now explicitly requires verified writes, filters, ranking, and invalidation. The harness map now treats skill discovery/activation as a separate evaluation target from skill quality after loading.
- **Challenged:** “A good skill file improves an agent” is too coarse. The observed effect was model-dependent, and a useful skill may never influence behavior if activation fails.
- **Still uncertain:** Whether the skills result generalizes beyond smart-contract auditing; whether vendor-generated user profiles improve production outcomes versus a custom derived view; and which memory policies best handle contradiction, freshness, and deletion over long-running assistants.

## Decisions and actions

- **Study deeply:** MCP 2.1.0's authorization flow: request authentication → resource/scope challenge → bounded parsing → handler dispatch.
- **Prototype/test:** Add memory-contract tests for rejected writes, idempotent retry, filter enforcement, ranking monotonicity, stale-memory replacement, and visible failure.
- **Record only:** LangGraph durable enqueue, Langfuse experiment UX, Claude Code policy/telemetry controls, and TRL kernel/API changes.
- **Ignore/watch:** Exact model IDs, vendor profile methods, SDK option names, and routine release churn unless a representative workload or failure requires them.

## Three highest-priority items

1. Read the MCP TypeScript SDK 2.1.0 server/core release notes and map the authorization boundary onto the current MCP/Nango architecture.
2. Use the Mem0 2.2.1 failures as a test checklist for any memory or retrieval layer, regardless of vendor.
3. Read the agent-skills paper for its separation of skill design, triggering, and downstream behavior; do not generalize the performance numbers beyond its domain.

## One recommended investment

**Four hours: build a memory correctness harness around one small Temporal-backed agent.**

- **45 min:** define ownership: Temporal workflow state vs working memory vs durable semantic/episodic memory.
- **90 min:** implement six invariant tests: rejected write, retry/idempotency, exact filter, ranking order, stale contradiction, and deletion/invalidation.
- **60 min:** run the cases with traces and label failures as write, retrieve, rank, context-assembly, or model-use failures.
- **45 min:** write a one-page architecture note with the owner and source of truth for every stateful component.

**Expected output:** a repeatable test suite and an explicit answer to “Where does Temporal end and agent-managed memory begin?”
