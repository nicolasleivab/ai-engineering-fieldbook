# Weekly Update — 2026-10-25

## Executive summary

The steady-state plan holds, but three stances sharpen this week. AuthorizationBench shows that task completion, extra reasoning, and conventional harm checks do not reliably keep an agent within delegated authority; deterministic pre-dispatch policy and explicit consultation remain necessary. Claude Code's sandbox fixes expose where such policy actually fails in production—shell startup files, symlink resolution, redirects, nested commands, delegated agents, and retry behavior—while Promptfoo 0.125.0 makes variance, cache disclosure, and safe evaluator execution first-class. On the evolving frontier, REM provides concrete evidence that memory quality depends on what is stored, when richer experience is injected, and when it is forgotten—not retrieval accuracy alone—and MCP's Skills extension makes portable skill catalogs an integrity-checked interface. The highest-value experiment is therefore an authorization conformance pack around one real tool workflow, not a new framework or fine-tuning run.

No post-training, fine-tuning, or custom-model result from the completed week cleared the threshold for changing the plan. The evidence still favors correcting authorization, isolation, evaluator, and memory-policy behavior before adapting model weights.

## Impact on the knowledge map

- **Confirmed:** Authorization is independent of task completion and consequence-oriented safety. Sandbox policy must cover canonical targets, implicit shell initialization, redirects, delegated work, and retries. Eval reports need stability and cache provenance.
- **Changed:** Memory is now evaluated by future-action improvement under interference and change, with explicit store/recall/forget policies. Skills are treated as versioned, integrity-checked supply-chain inputs rather than trusted prompt folders. Security policy must inherit through delegation and operate on canonical resource identities.
- **Challenged:** More reasoning does not reliably repair authorization alignment. Better retrieval—even oracle retrieval of the same experience—does not guarantee better agent behavior. A sandbox rule expressed only against the requested path is not necessarily a boundary.
- **Still uncertain:** AuthorizationBench's production generality; how often consultation harms useful autonomy; whether REM transfers beyond related coding tasks; the right trust/signing model for distributed skill catalogs; and which repeat count best estimates agent reliability economically.

## Decisions and actions

- **Study deeply:** AuthorizationBench's controlled pairs and consultation behavior; REM's lifecycle ablations.
- **Prototype/test:** Authorization scope at dispatch, canonical-path and shell-startup isolation, policy inheritance to subagents, idempotency-aware retry, repeated-run stability, cache disclosure, and verified skill loading.
- **Record only:** MCP Ruby conformance changes, LangGraph priority settings, Langfuse skill-management APIs, and AAIF governance claims.
- **Ignore/watch:** Model-launch rankings, skill-installation counts without quality evidence, and post-training work that lacks a task-specific advantage over a corrected harness.

## Three highest-priority items

1. Turn AuthorizationBench into 10–12 paired cases for one real workflow: authorized versus adjacent out-of-scope actions, benign pressure, direct harm versus no visible harm, and an explicit ask-the-principal route.
2. Add boundary cases from Claude Code's fixes: shell startup, symlinked targets, redirects, nested commands, delegated agents, protected configuration, and connection-loss retries.
3. Prototype a small REM-style memory policy: store a phase-structured lesson, withhold detailed implementation history until a struggle signal, evict it after one exposure, and compare task success and cost against eager injection.

## One recommended investment

Spend **four focused hours** building an authorization conformance pack around one MCP or external-action workflow:

- **45 min:** define the principal, allowed actions, forbidden adjacent actions, consultation trigger, and authoritative policy state.
- **75 min:** create 10–12 paired cases covering benign pressure, harmful and apparently harmless scope violations, symlinks/aliases, delegation, and retry after connection loss.
- **60 min:** run each case three times with the current harness; record completion, unauthorized-action, consultation, block, cache, and latency outcomes.
- **45 min:** add a deterministic pre-dispatch guard on canonical tool/resource identity and propagate it to delegated agents.
- **15 min:** rerun failures and write deploy-blocking thresholds.

**Expected output:** a before/after authorization-violation rate plus a portable regression suite that distinguishes useful autonomy from scope drift. For a production Temporal/MCP/Composio-style stack, this is more valuable now than adding another agent framework or beginning fine-tuning.
