# Weekly Update — 2026-10-18

## Executive summary

Week 4 closes with a stronger production-hardening rule: compaction, approval, recovery, and evaluator execution are control-plane state transitions, not background plumbing. OpenAI Agents SDK 0.24.0 and LangGraph 1.2.16 shipped fixes around pending approvals, retained tool outputs, partial writes, and exactly-once resume behavior; an oracle-integrity study separately showed that evaluator-side state mutation could inflate measured success from 65.5% to 94.3%. Skill observability is also becoming operational: Langfuse now traces skill availability, resource loads, and version-specific use, while Claude Code exposes permission-classifier decisions. TRL's post-training efficiency work is worth recording, but it does not justify adaptation before the fieldbook's eval and recovery invariants are executable. The catch-up sequence is complete; move to steady-state frontier review with at most one targeted experiment per week.

## Impact on the knowledge map

- **Confirmed:** Recovery and compaction are state-machine transitions. Skill activation/resource loading must be observed separately from downstream task behavior. Evaluators require their own tests and failure taxonomy.
- **Changed:** Context policy now explicitly forbids compaction across unresolved approvals unless the approval state is preserved. Reliability now includes oracle state integrity, non-interference, and reconstructible terminal state—not only grader outputs and runner exits.
- **Challenged:** “Compaction is just token optimization” and “a deterministic evaluator is automatically trustworthy.” Both can alter authoritative control or environment state.
- **Still uncertain:** Whether the oracle-audit findings generalize across benchmark types; how to coordinate compaction across concurrent writers; which skill-load metrics correlate with production success; whether TRL's gains persist across models and rollout shapes; and whether generated proxy benchmarks remain faithful under rapid model change.

## Decisions and actions

- **Study deeply:** The oracle-integrity invariants and known-answer controls; OpenAI Agents SDK's recovery/readiness notes around pending approvals and partial writes.
- **Prototype/test:** Pending-approval compaction, partial-write reconciliation, exactly-once resume, oracle non-interference, and capability-ablated skill evals.
- **Record only:** Claude Code and Langfuse product controls, MCP Ruby SDK surface details, and TRL's hardware/packing optimizations.
- **Ignore/watch:** Automatically generated benchmarks without held-out-model validation; efficiency claims without workload details; framework releases that do not expose a new failure class.

## Three highest-priority items

1. Turn OpenAI Agents SDK 0.24.0 and LangGraph 1.2.16's recovery fixes into framework-independent tests: pending approvals survive compaction, completed effects are not replayed, partial writes are reconciled, and resume updates apply once.
2. Read and run the oracle-integrity replication package; add pre/post environment hashes, known-answer controls, and a requirement that the reference terminal state be reconstructible.
3. Instrument one skill-using workflow with four separate events: offered, selected, resource loaded, and behavior succeeded; then run a tool/skill ablation.
