# Weekly Update — 2026-10-04

## Executive summary

This week did not produce a new agent architecture worth adopting. It produced stronger evidence for a more durable point: most production failures now sit at ownership and boundary transitions—agent-to-agent state, approval scope, checkpoint-to-UI reconciliation, credential audience, redirects, retries, and destructive filesystem actions. MCP and agent SDK releases tightened those transitions, while E2B made retry policy explicitly depend on whether an operation is safe to replay. The learning plan should therefore move to Week 3 as planned: build an eval baseline that includes state, permission, cancellation, and retry failures before considering post-training.

## Impact on the knowledge map

- **Confirmed:** tool calls need resource bounds and audience-bound credentials; durable persisted state must outrank transient UI/stream state; generated-code execution needs deterministic protection outside the model.
- **Changed:** the harness stance now makes per-run/per-agent state and approval ownership explicit. The state stance now requires reconciliation after cancellation and resume. The execution stance now limits automatic retries to operations known safe to replay.
- **Challenged:** nothing fundamental. The week challenged optimistic assumptions that framework abstractions already isolate nested state, approvals, retries, and projections correctly.
- **Still uncertain:** which ownership and recovery invariants deserve reusable cross-framework conformance tests; which eval failures best predict production incidents; whether post-training is useful after these harness failures are removed.

## Decisions and actions

- **Study deeply:** state ownership, idempotency, authoritative persistence, and projection reconciliation.
- **Prototype/test:** add adversarial cases for nested-agent state leakage, wrong-agent approval reuse, cancellation/resume, ambiguous POST retry, cross-origin redirect, wrong token audience, and oversized structured input.
- **Record only:** MCP option names, Claude Code controls, and the Evals-to-Datasets migration surface.
- **Ignore/watch:** model launches and unvalidated agent papers that do not provide reproducible evidence or change an engineering decision.

## Three highest-priority items

1. Read the [OpenAI Agents Python 0.23.0 release](https://github.com/openai/openai-agents-python/releases/tag/v0.23.0) as a ready-made failure taxonomy; turn at least five fixes into framework-independent eval cases.
2. Read the [MCP TypeScript SDK 2.3.0 upgrade notes](https://github.com/modelcontextprotocol/typescript-sdk/releases/tag/v2.3.0), then test audience mismatch, cross-origin redirect, input cardinality, and stateless request isolation.
3. Read the [E2B 2.52.0 retry notes](https://github.com/e2b-dev/E2B/releases/tag/e2b%402.52.0) and audit every automatic retry in the prototype as safe, keyed, or reconciled.

## One recommended investment

Spend **four focused hours** building the Week 3 baseline: 45 minutes to define 15–20 representative tasks, 90 minutes to run and annotate traces, 45 minutes to create a failure taxonomy, 45 minutes to add targeted checks for state/approval ownership, cancellation/resume, and retry ambiguity, and 15 minutes to decide whether the next change belongs in the harness, retrieval, tools, or model. Expected output: a portable task set plus a short baseline report. Do not fine-tune this week unless the report shows a repeated model-behavior failure after context and harness errors are excluded.
