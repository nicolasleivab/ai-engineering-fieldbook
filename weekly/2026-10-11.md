# Weekly Update — 2026-10-11

## Executive summary

The Week 3 plan still holds: build a trustworthy eval baseline before attempting post-training. This week's strongest evidence is that the evaluator itself is part of the system under test—Promptfoo fixed multiple cases where graders, score transforms, missing dependencies, or process exit codes could report the wrong result. LangGraph's checkpoint fixes and Claude Code's compaction and gating-hook fixes add a second lesson: replay, compaction, and policy enforcement are state transitions with invariants, not formatting details. AgentPrivArena adds a third: final-answer success misses privacy failures caused by unnecessary reads or unsafe information flows during the tool trajectory. The knowledge map now makes grader validation, checkpoint-branch isolation, fail-closed gates, and trajectory-level privacy auditing explicit; the coming week should advance to Week 4 production hardening with a small cross-framework conformance pack.

## Impact on the knowledge map

- **Confirmed:** End-to-end outcomes are necessary but insufficient; production evals also need trajectory, state-transition, permission, and component-level assertions. Persisted state remains authoritative, and filesystem/tool isolation must be deterministic.
- **Changed:** Reliability now requires golden tests for graders and runner failure semantics. State now requires explicit forks when replaying or updating historical checkpoints. Context compaction must preserve committed actions and provenance. Security now includes data-minimizing reads, outbound-flow auditing, and fail-closed deterministic gates.
- **Challenged:** A successful final answer does not imply privacy-safe execution. A familiar evaluation score is not trustworthy merely because the runner completed. Updating an old checkpoint in place is not a valid shortcut for branching history.
- **Still uncertain:** How well AgentPrivArena's privacy metrics generalize beyond its services; the false-positive and latency cost of runtime flow arbiters; whether RIT-RAG's gains survive production corpus drift; and which conformance cases best predict real incidents across frameworks.

## Decisions and actions

- **Study deeply:** AgentPrivArena's distinction between accessed data, accumulated context, and outbound information flow; Promptfoo's grader failure taxonomy.
- **Prototype/test:** Add golden grader cases, historical-checkpoint fork tests, compaction action-ledger tests, failed-gate behavior, unnecessary-read detection, and outbound-write policy checks.
- **Record only:** MCP legacy-package parity, Langfuse evaluator UI changes, managed-worktree APIs, and product-specific hook or sandbox flags.
- **Ignore/watch:** Model-launch churn, benchmark headlines without artifacts, and post-training work that has no demonstrated advantage over fixing the harness or data.

## Three highest-priority items

1. Convert the Promptfoo 0.124.0 fixes into framework-independent tests for score bounds, negation, malformed grader output, missing dependencies, process exit status, and replay isolation.
2. Read AgentPrivArena's environment and metric design, then add one unnecessary-read assertion and one outbound-flow assertion to a representative MCP agent.
3. Test historical checkpoint replay as a fork: the selected checkpoint produces a new branch, sibling state remains unchanged, and resolved interrupts do not reappear.

## One recommended investment

Spend **four focused hours** building a Week 4 agent-harness conformance pack:

- **45 min:** create golden evaluator cases for pass/fail inversion, score bounds, malformed output, missing dependencies, and runner failure.
- **60 min:** add historical-checkpoint replay, sibling isolation, and resolved-interrupt tests.
- **75 min:** instrument one MCP workflow with an access inventory plus pre-write privacy assertion.
- **30 min:** test compaction across a completed side effect and verify that the action is neither repeated nor retracted.
- **30 min:** test a failed or timed-out policy gate and require a blocked action with visible diagnostics.

**Expected output:** a portable 10–15-case suite that can run against Temporal/MCP and any agent framework before deployment. This is a better Week 4 investment than fine-tuning: it establishes whether later model or harness changes are genuinely safer and more reliable.
