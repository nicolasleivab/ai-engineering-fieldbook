# Weekly Update — 2026-11-15

## Executive summary

This week turns several previously abstract boundaries into executable engineering tests. Six MCP reference-server vulnerabilities show that canonical path checks are insufficient when authorization and use can refer to different objects, and that a semantically read-only Git operation can execute attacker-controlled repository configuration. Continual-ARC makes an equally important distinction for memory: persistence can help reuse a known task, but it is not continual learning and did not produce unseen-task generalization in the tested harnesses; weight-based learning did. WorkflowArena, CoReMem, CAMP-II, drydock-eval, and Temporal add useful evidence on workflow topology, prospective memory value, interface priors, evaluator conformance, and replay safety. The steady-state plan remains correct: run one bounded tool-boundary conformance experiment rather than adopt a framework, memory layer, or training stack.

## Impact on the knowledge map

- **Confirmed:** Replay-safe durable workflows require deterministic runtime enforcement; evaluator results require clean containment, request/grader conformance, and repository-aware paired statistics; workflow topology is a capability distinct from model execution; memory value remains task-conditioned and cost-sensitive.
- **Changed:** Tools now bind authorization and use to the same opened object and neutralize ambient executable configuration. Execution now treats semantic read-only as potentially side-effecting. Memory now distinguishes persistence, seen-task reuse, and unseen-task generalization, with cache and parametric-learning baselines.
- **Challenged:** Canonicalize-then-open, “read-only means safe,” “the harness persisted something, therefore it learned,” and one aggregate multi-agent score are not defensible defaults.
- **Still uncertain:** Whether Continual-ARC's negative harness results transfer to production domains; whether CoReMem and CAMP-II reproduce outside their authors' pipelines; which workflow topologies win under fixed cost and latency; and how to implement object-bound confinement portably on Windows.

## Decisions and actions

- **Study deeply:** Read the MCP v2.4 advisories together with Continual-ARC. Extract two reusable distinctions: checked name versus opened object, and persisted artifact versus measured learning.
- **Prototype/test:** Add a small semantic-read-only boundary suite covering malicious Git configuration, a symlink-swap attempt, a special file, and a fetch target that changes identity. Run it against pinned pre-fix and patched MCP servers inside an isolated environment; assert no command execution, out-of-scope read, hang, or network escape.
- **Record only:** Temporal 1.36 replay fixes, WorkflowArena's workflow-author/executor split, CAMP-II's interface-prior lesson, and Langfuse's version-specific accounting/RBAC changes.
- **Ignore/watch:** Do not switch orchestration frameworks, memory vendors, or post-training stacks. Wait for independent replication and first run the bounded boundary suite.

### Three highest-priority items

1. **Upgrade and test:** Read the MCP [v2.4.0 release](https://github.com/modelcontextprotocol/servers/releases/tag/v2.4.0) and [security advisories](https://github.com/modelcontextprotocol/servers/security/advisories), then verify the four boundary cases above against the exact versions you deploy.
2. **Read and run a floor:** Read [Continual-ARC](https://arxiv.org/abs/2611.14505) and reproduce one seen-task comparison with no persistence, demonstration cache, and the current memory policy before calling the system “continually learning.”
3. **Adapt one evaluator check:** Read [Contain, Conform, Compare](https://arxiv.org/abs/2611.16485) and add one rendered-request golden test plus repository-clustered paired comparison to the existing eval loop.

## One recommended investment

Spend **four focused hours** building the semantic-read-only boundary suite. Allocate 45 minutes to pinning the vulnerable and fixed MCP versions in a networkless sandbox, 150 minutes to the four cases (Git command-bearing config, filesystem symlink swap, special file, and fetch identity/private-address handling), and 45 minutes to a pass/fail matrix recording effective UID, network policy, opened resource identity, timeout, and side effects. Stop when the matrix and version recommendation are reproducible; do not expand into a general sandbox project this week.
