# Weekly Update — 2026-11-22

## Executive summary

This week strengthens three boundaries already emerging in the fieldbook. MCP reference-server fixes again show that a confined path is not a confined operation when repository configuration can redirect execution; code-context research adds that independently fresh source, indexes, and graphs can still form an invalid mixed-revision view; and anytime coding-agent evaluation shows that passing self-tests is not enough evidence to stop. FrontierHarness and SWE-CoWork add complementary evidence that capability belongs to the model–harness–workflow combination, not the model alone, and that requirements need an explicit lifecycle across clarification, implementation, verification, and handoff. No memory-system or post-training result this week clears the bar to change the existing persistence-versus-learning stance. The plan stays in steady state: upgrade exposed MCP servers, then run one bounded anytime-evaluation experiment rather than adopt a new framework or stopping policy.

## Impact on the knowledge map

- **Confirmed:** Repository-driven configuration remains an executable boundary that must be neutralized and revalidated after mutations; clarification, approval, and recovery are durable workflow state; sandbox performance is an optimization layer, not evidence of isolation; memory persistence still does not imply continual learning.
- **Changed:** Context now requires one revision identity and atomic publication boundary across source and derived views. Models are selected as versioned model–harness pairs rather than independently. Reliability now retains intermediate states and requires hidden-test non-inferiority before promoting stopping policies.
- **Challenged:** Independently fresh indexes imply consistent context; a passing self-test means the agent should stop; a model or harness has an intrinsic rank independent of its pairing; and asking the right colleague once means a requirement has been carried to verified completion.
- **Still uncertain:** Whether complete-revision publication scales to large, continuously edited monorepos; which stopping features generalize beyond SWE-bench; whether FrontierHarness rankings reproduce independently; and whether Readie's latency gains preserve strong tenant isolation and clean snapshot provenance.

## Decisions and actions

- **Study deeply:** Read the revision-publication and anytime-evaluation papers together. Extract two reusable contracts: one coherent world per model turn, and one cost/quality point per intermediate trajectory state.
- **Prototype/test:** Upgrade MCP Git/filesystem servers to the v2.5 fixed packages and extend the existing boundary suite with maintenance, lazy-fetch transport, post-checkout config-include, empty-driver, and unsafe-index cases. Separately, use archived coding-agent trajectories for the four-hour anytime evaluation below.
- **Record only:** FrontierHarness's model–harness interaction, SWE-CoWork's requirement ledger, Readie's pre-warmed snapshot strategy, and the OpenAI checkpoint/approval migration details.
- **Ignore/watch:** Do not choose a harness from one aggregate leaderboard, deploy a learned stopping rule, or adopt a new sandbox/post-training/memory stack. No memory or custom-model result this week justifies a plan change.

### Three highest-priority items

1. **Upgrade and regression-test MCP:** Read the [v2.5.0 release](https://github.com/modelcontextprotocol/servers/releases/tag/v2.5.0), verify the installed Git/filesystem package versions, and run the new repository-configuration cases against the exact deployment image.
2. **Turn one coding eval into an anytime eval:** Read [Done, But Still Working](https://arxiv.org/abs/2611.22901), retain each distinct patch plus cumulative cost, and compare earliest hidden-test success, final success, and regressions before considering any stop rule.
3. **Add one revision-publication invariant:** Read [Revision-Consistent Code Context](https://arxiv.org/abs/2611.21616) and make a rename/delete test fail whenever source, symbol, and graph views do not share the same published revision ID.

## One recommended investment

Spend **four focused hours** converting one existing coding-agent evaluation into an anytime evaluation. Allocate 45 minutes to capturing or parsing every distinct patch with cumulative tokens, wall time, and self-test status; 120 minutes to replaying at least ten archived trajectories against hidden tests at each checkpoint; 45 minutes to calculate earliest-correct, final-correct, later-regression, and cost-to-correct distributions; and 30 minutes to write a decision note for one candidate rule such as “same patch passes twice.” Stop with the dataset, chart, and go/no-go criterion; require paired hidden-test non-inferiority before any runtime change.
